# Calculators

## Calculator page headings are one Setting; the "About" body stays elsewhere
Meta title/description, h1 and intro for /calculators and every calculator page (plus the "About" heading on eligibility/prepayment) live in ONE nested Setting `calculator_pages` (keys: index, emi, eligibility, prepayment, fixed_deposit, sip, daily_sip, gst), resolved by App\Support\Calculators\CalculatorPagesContent and edited at Website Settings → Calculators Page (View:CalculatorPagesSettings, granted to Marketing). Loan calculators share copy per type; `{loan}` becomes the LoanCategory label via forPage($page, $category). Blank field → default; reset stores null. Do NOT duplicate the "About" body here — it lives on CalculatorPage (Content → Calculator Pages), one row per calculator page. Breadcrumbs and calculator links (CalculatorCatalog) are intentionally not editable.

## Calculator indexing is a separate Setting that stores HIDDEN pages
Per-calculator search indexing lives in App\Support\Calculators\CalculatorIndexing (Setting `calculator_pages_indexing` = {enabled, noindex[]}), edited in the "Search engine indexing" section of Website Settings → Calculators Page. It is kept OUT of `calculator_pages` so "Reset to defaults" (wording) never re-indexes/de-indexes pages. It stores the noindexed page keys (path under /calculators: `index`, `gst`, `emi/home-loan`), so a missing row or a new CalculatorCatalog entry is indexable by default. Hidden pages render `noindex, follow` via the controller's `robots` view var and are filtered out of Sitemap::calculators(). Any new calculator view must pass `:robots="$robots"` to the layout. The sitewide SearchEngineIndexing switch still wins.

## Calculator "About" content is one CalculatorPage row per calculator page
Every CalculatorCatalog page (FD/SIP/GST and every EMI, Eligibility and Prepayment page) gets its "About" heading and body from CalculatorPage via CalculatorPage::aboutFor(). The row's calculator_key is CalculatorIndexing::pageKey(), the same path key the indexing setting uses (`gst`, `emi/home-loan`). The admin picks it from CalculatorCatalog::pages() in Content → Calculator Pages. Loan pages with no row fall back to LoanProduct::calculator_explanation (then `summary` for the standalone EMI panel). That field is shared by all three calculators of a loan type, so it is only a fallback. Blank editor markup (`<p></p>`, `&nbsp;`) counts as no content and hides the section. The default heading is "About the {catalog label}"; Eligibility/Prepayment default to CalculatorPagesContent about_heading instead. The standard EMI page's About block lives inside ⚡emi-calculator (the `about` computed property, which follows the tab switcher). emi.blade.php only renders x-site.calculator-explainer for the Flexi Hybrid branch. A new calculator only needs a CalculatorCatalog entry. It needs no migration and no enum case.

## Per-page headline/intro overrides live on CalculatorPage
Refines "Calculator page headings are one Setting". `calculator_pages` (CalculatorPagesContent) holds the SHARED wording for each calculator type. A CalculatorPage row (Content → Calculator Pages, keyed by the page path such as `emi/home-loan`) can override heading, description, meta_title and meta_description for that one page. Blank fields keep the shared wording. CalculatorController::contentFor() applies the override with CalculatorPage::contentFor(). /calculators (index) has no override. `{loan}` is NOT substituted in per-page overrides.
