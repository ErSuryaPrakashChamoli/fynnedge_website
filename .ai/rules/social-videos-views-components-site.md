# Social Videos Views Components Site

## Social media videos: own model, shared player, CMS-worded section
SocialVideo (Admin → Content → Social media videos) re-shows clips FynnEdge posted on Instagram/Facebook/LinkedIn/YouTube. Footage is uploaded (social-videos/, covers in social-video-covers/, both in MediaRegistry) or a YouTube link; the original post is only LINKED (post_url, http(s) only via postUrl()), never embedded — no Meta/LinkedIn script, cookie or CSP frame-src change. Playback logic lives in the HasPlayableVideo trait shared with VideoTestimonial (one youtubeIdFrom() validator); cards dispatch `open-video-testimonial` and the layout's single x-site.video-testimonial-player renders when EITHER VideoTestimonials or SocialVideos::forCurrentPage() is non-empty. Placement = FAQ vocabulary + 'all', default home; x-layouts.app renders x-site.social-videos after the slot unless the view passes `handles-social-videos` (home does, placing it directly above x-site.video-testimonials). Eyebrow/heading/intro/optional button come from MarketingSection placement `social_videos` (subheading = badge) with built-in fallbacks; follow icons come from Settings social_* URLs. Cards mirror x-site.video-testimonials cards row for row (16:10 video; "▶ title" truncated to one line; cardLabel() (the admin's "Short info" `tagline`, falling back to the platform name; translatable via tagline_hi) across the full avatar row — no icon there, the user removed it — in a min-h-10 block: one truncated line above "View on …", or line-clamp-2 leading-5 when there is no post link; caption as one fixed h-4 line where the stars sit) and the intro is max-w-2xl so follow icons/arrows share the heading row — the user requires both sections to be the same height (2026-10-14); the earlier portrait 4:5 card was rejected. Marketing role access is granted by RoleSeeder AND migration 2026_10_14_144416 (deploys never run the seeder). Pinned by SocialVideoPlacementTest and SocialVideoResourceTest.
